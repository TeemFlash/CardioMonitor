# CardioMonitorApp — Android-прототип

Это отдельное приложение для телефона на Kotlin и Jetpack Compose. Оно не входит в прошивку ESP32-C3 и не копируется на microSD устройства. [Прошивка и её руководство](../Monitor%20soft/README.md) находятся в соседней папке.

**Текущий статус: исходный каркас, интеграция с устройством не завершена.** В приложении написаны клиент TLS, модели данных, сохранение в Room/SQLCipher, экран текущих показаний и список истории. Однако текущая прошивка не реализует сервер этого протокола. Само подключение ESP32 к Wi-Fi не запускает передачу показаний на телефон. Импорта CSV с SD также нет.

В этой папке нет реализованного медицинского анализатора ЭКГ или функции постановки диагнозов. Анализ истории, который работает на экране самого устройства, описан в руководстве прошивки и автоматически в Android не переносится.

## Как проходят данные

1. `CardioMonitorApp` открывает локальную БД и создаёт `AnalysisRepository` с `DeviceConnectionManager`.
2. `MainActivity` создаёт `LiveMonitorViewModel`. Его инициализация сразу вызывает `repository.startListening()`; отдельной кнопки выбора устройства пока нет.
3. Сетевой менеджер пытается открыть TLS-соединение и превращает пакеты в `IncomingEvent`.
4. Репозиторий записывает события в Room и обновляет потоки `liveEcg`, `livePulse`, `liveSpo2`.
5. Экран мониторинга получает эти потоки через ViewModel. Список истории получает `Flow` таблицы сессий из Room.

Событие `session_started` должно прийти до ЭКГ: отсчёты без активной сессии отбрасываются. Пульс и SpO₂ без сессии показываются в live-режиме, но не сохраняются. При `session_started`/`session_ended` границы сессии записываются по часам телефона; временные метки отдельных измерений приходят из пакетов. Их начало отсчёта ещё нужно согласовать с устройством.

Хранилище Android находится **в памяти телефона**. Оно не читает SD-карту ESP32 напрямую и не заменяет запись CSV прошивкой. Окно live-ЭКГ ограничено 500 точками, но список истории и полная выбранная сессия сейчас загружаются целиком; для длинных записей потребуется постраничное чтение. Ограничения RAM прошивки из соседней папки к этому коду автоматически не относятся.

## Протокол, который ожидает клиент

Это описание текущего парсера приложения, **не уже реализованный протокол прошивки**. Клиент ожидает поток пакетов поверх одного TLS-соединения:

```text
[type: UInt8][payloadLength: Int32 big-endian][payload: payloadLength bytes]
```

Длина должна быть неотрицательной. Ограничение максимального размера и проверку длины до выделения памяти ещё необходимо добавить.

### Тип `0x01`: JSON в UTF-8

```json
{"type":"session_started","session_id":"session-001","device_id":"cardio-001"}
```

```json
{"type":"pulse","ts":1234567890,"bpm":72}
```

```json
{"type":"spo2","ts":1234567890,"value":98}
```

```json
{"type":"session_ended","session_id":"session-001"}
```

`ts` — целое количество миллисекунд. В показанном формате отсутствуют флаги качества измерения, параметры автонастройки MAX30102 и метаданные фильтра ЭКГ. Для обмена с текущей прошивкой их нужно добавить и согласовать с её CSV/моделями.

### Тип `0x02`: бинарные отсчёты ЭКГ

```text
[timestampMs: Int64 big-endian][value: Float32 big-endian]
```

Один отсчёт занимает 12 байт, пакет содержит несколько отсчётов подряд. Сейчас парсер читает только полные группы по 12 байт и игнорирует остаток; строгую проверку кратности длины ещё нужно реализовать. `value` нельзя подписывать как микровольты до определения единиц и калибровки тракта.

Подтверждений доставки, запроса истории с SD, команд управления записью и версии протокола в текущем коде нет.

Обновление документации не означает, что Android-сборка прошла. CI репозитория проверяет прошивку, Android-тестов и Android-сборки в нём пока нет.

Для работы нужны Android Studio, JDK 17, Android SDK Platform 34, Platform Tools и доступ к репозиториям зависимостей. Открывать в Android Studio нужно именно папку `CardioMonitorApp`.

Локальный путь SDK задаётся Android Studio в **неотслеживаемом** `local.properties`, например:

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

После проверки/согласования версий инструментов команды запускаются из `CardioMonitorApp/`:

```sh
./gradlew --version
./gradlew :app:assembleDebug
```

В Windows используются `gradlew.bat --version` и `gradlew.bat :app:assembleDebug`. При успешной сборке debug APK появляется в `app/build/outputs/apk/debug/app-debug.apk`. Эта команда не прошивает ESP32. Открывать и собирать прошивку нужно по [отдельной инструкции](../Monitor%20soft/README.md).

## Что ещё блокирует готовое приложение

### Связь и защита данных

- **Нет интеграции с прошивкой.** Нужны согласованный протокол, сервер/экспорт на ESP32 и экран подключения в приложении. Сейчас используются фиксированные IP/порт и отсутствует процедура спаривания.
- **Сертификат устройства не проверяется как закреплённый.** Аргумент `trustedCertPem` не используется внутри `buildPinnedSslContext`; `SSLContext.init(null, null, null)` выбирает стандартные менеджеры доверия. Явная проверка имени/идентичности сервера для сырого `SSLSocket` также не настроена. Само наличие TLS не означает реализованную проверку именно нашего устройства.
- **Ключ SQLCipher — постоянная заглушка.** Строка `REPLACE_WITH_KEYSTORE_DERIVED_KEY` находится в исходнике. БД использует SQLCipher, но защита секретом конкретного телефона ещё не реализована. Нужна генерация случайного секрета БД и его защита через Android Keystore.
- **Биометрической блокировки нет.** Зависимость, permission и комментарий не вызывают `BiometricPrompt`.
- **Сетевой слой требует доработки.** Нет ограничения длины пакета перед `ByteArray(length)`, контроля переполнения `trySend`, автоматического переподключения и read-timeout. После ошибки `finally → disconnect()` заменяет состояние `Error` на `Disconnected`, поэтому сообщение об ошибке может исчезнуть. Закрытие сокета при отмене жизненного цикла нужно связать явно.

### Интерфейс, история и жизненный цикл

- **Детали истории не подключены.** Нажатие на сессию ведёт в маршрут с незавершённым содержимым; существующий `SessionDetailScreen` нужно вызвать через ViewModel.
- **Средние не рассчитываются.** Поля `averageBpm`/`averageSpo2` создаются как `null` и не обновляются при завершении сессии.
- **Нет анализа сигналов и советов в Android.** Приложение принимает значения; в нём нет переноса правил анализа истории из прошивки, оценки пригодности сигнала или диагностики ЭКГ.
- **Нет импорта/экспорта и графика всей записи.** Полная сессия читается в списки, а экран деталей содержит только счётчики и текстовую сводку.
- **ViewModel создаются вручную.** Нужно подключить стандартное управление жизненным циклом, чтобы пересоздание Activity не оставляло старые слушатели и не запускало лишние соединения. Сейчас завершение `viewModelScope` не привязано к `ViewModelStore` через обычную фабрику.
- **Нет миграций и настроенного экспорта схем Room.** Перед изменением БД нужно сохранять её схему и определять миграции, чтобы история пользователя переживала обновления.
- **Нет автоматических Android-тестов.** Проверки парсера, БД, навигации и жизненного цикла ещё нужно добавить вместе с соответствующими доработками.

## Какие локальные файлы не нужны в Git

Правила исключения находятся в [корневом `.gitignore`](../.gitignore).

| Путь/тип | Что это и можно ли удалять |
| --- | --- |
| `app/build/`, `build/` | Сгенерированные APK, классы, отчёты и промежуточные результаты; восстанавливаются сборкой. |
| `.gradle/`, `.kotlin/` | Локальные кэши; восстанавливаются, первая следующая сборка может занять больше времени. |
| `.idea/`, `*.iml` | Состояние IDE. Не требуется для сборки; удаление сбрасывает часть пользовательских настроек проекта. |
| `*.hprof` | Дампы Java-кучи после сбоя. Для сборки не нужны; могут содержать данные процесса и занимать много места. |
| `local.properties` | Локальный путь SDK. Не нужен в репозитории, но полезен на рабочем компьютере; удаление может потребовать повторного выбора SDK. |
| `*.jks`, `*.keystore`, `key.properties` | Ключи и параметры подписи. Не публиковать и не удалять автоматически: это не восстанавливаемый кэш. |
| БД и личные записи измерений | Пользовательские данные, а не исходники; не добавлять в репозиторий и не удалять при очистке сборки. |

`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`, `gradle-wrapper.properties`, Gradle-конфигурация и весь `app/src/` остаются в репозитории. Незавершённый экран деталей и модели — полезные исходники, даже если пока не подключены к пользовательскому сценарию.

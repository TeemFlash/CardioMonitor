# Обмен с Android в локальной Wi-Fi-сети

ESP32-C3 и телефон подключаются к одной локальной сети. Откройте CardioMonitor на
телефоне: IP вводить не нужно. Прибор объявляет сервис `_cardiomonitor._tcp` через
mDNS, приложение находит его средствами Android NSD. Для локального обмена интернет и Firebase не нужны. Для первичной синхронизации
часов ESP32 по NTP нужен интернет.
ESP32 работает с Wi-Fi 2,4 ГГц; телефон может быть на 5 ГГц того же роутера, если
роутер объединяет эти сети и разрешает связь клиентов и multicast.

## Пользовательский сценарий

1. На приборе: Настройки → Wi-Fi → подключиться к сети.
2. На телефоне: подключиться к той же сети и открыть CardioMonitor.
3. Во вкладке «Устройство» появляется состояние связи и синхронизации.
4. Запустите нужное измерение на приборе. Главная приложения отображает доступные
   достоверные значения и, в режиме ЭКГ, поток отсчётов. В меню измерений нет.
5. Завершённые CSV автоматически копируются с microSD. Проверка новых записей идёт
   каждые 15 секунд; кнопка «Синхронизировать записи» запрашивает проверку немедленно
   после текущей операции. Открытый файл записи копируется только после закрытия.
6. В «Записях» доступны средние значения, график с прокруткой, экспорт оригинального
   CSV и удаление телефонной копии. На SD ничего не удаляется. Удалённая на телефоне
   копия не восстанавливается автоматически при очередной проверке.

При потере связи значения и график очищаются после тайм-аута чтения (до 5 секунд),
соединение восстанавливается автоматически. Режим фонового сервиса не реализован:
для надёжной синхронизации держите приложение открытым. Android может остановить
его процесс в фоне или во сне. После запуска незавершённая передача повторяется.
Одновременно поддерживается один телефон с двумя TCP-соединениями.

## Что передаётся и где хранится

- Поток показаний: ЧСС, SpO₂, относительная фильтрованная ЭКГ, признаки пригодности
  сигнала, наличия пальца, заряд (если доступен), режим, состояние SD и записи.
- История: все `ecg_*.csv`, `pulse_*.csv`, `spo2_*.csv` в корне SD, с номером из
  1–9 цифр. Файлы настроек не передаются. Содержимое CSV сохраняется без изменений,
  включая исходные каналы, недостоверные строки и комментарии параметров обработки.
- На ESP32 нет копии архива в RAM: чтение SD идёт блоками 512 байт. Два буфера
  отправки по 4096 байт и кольцо 80 отсчётов имеют фиксированный размер. Сокеты
  неблокирующие; отправляется не более 1024 байт на клиента за проход основного цикла.
- На телефоне оригиналы находятся в приватном каталоге `files/sd_archive/<device>/`.
  Промежуточный `.part` удаляется при ошибке; CRC32 проверяется до импорта.
  Каталог файлов SD сначала сохраняется во временный файл, а не в массив RAM.
- Room хранит сессии и достоверные значения для интерфейса. Импорт CSV выполняется
  транзакцией и пакетами до 256 строк. Пульс/SpO₂ для статистики сохраняются не чаще
  раза в секунду; оригинал сохраняет все строки. График читает из БД только нужное
  четырёхсекундное окно (до 2000 точек), а не всю ЭКГ.
- Признак завершённого импорта — ID прибора, имя и размер файла в SharedPreferences.
  Повторная проверка не создаёт дубликаты. Предполагаются неизменяемые CSV прошивки;
  ручная замена файла другим содержимым той же длины не обнаруживается.
- Старый неизвестный формат остаётся в истории с пояснением и экспортируется как
  исходный CSV; значения из неизвестных столбцов не выдаются за измерения.
- Новые записи содержат `# started_at_unix_ms=<UTC миллисекунды>`: это начало
  измерения, а не время скачивания. ESP32 сам запускает SNTP при подключении Wi-Fi
  (`pool.ntp.org`, `time.google.com`); телефон не устанавливает часы прибора.
  Внутри CSV отсчёты остаются относительными. Если синхронизация случилась во время
  записи, дата начала вычисляется по прошедшим миллисекундам и добавляется комментарием.
  Первый сохранённый timestamp фиксируется для всей сессии.
- На телефоне дата показывается в его часовом поясе; на приборе в деталях истории —
  UTC с явной подписью. Раздел «Устройство» показывает часы ESP32 или «Ожидание NTP».
- После синхронизации время идёт и при потере сети, пока сохраняется питание.
  После полного выключения нужна новая синхронизация через интернет. Для сохранения
  времени без интернета и питания основной платы нужен внешний RTC с батарейкой,
  например DS3231; в текущей схеме его нет. До получения времени запись остаётся
  без абсолютной даты. Старые CSV без даты не датируются задним числом.

## Протокол v1

TCP-порт `8765`, UTF-8 JSON по строкам, команды ASCII с `\n`. mDNS hostname и поле
`device` имеют вид `cardio-<12 hex цифр идентификатора ESP32>`. Это идентификатор,
а не подтверждение подлинности. Начало соединения:

```json
{"type":"hello","version":1,"device":"cardio-0123456789ab"}
```

Команда `LIVE\n`: кадр примерно каждые 200 мс (5 обновлений/с), до 80 точек ЭКГ.
`hr` (оптический пульс), `ecg_hr` (ЧСС по ЭКГ), `spo2`, `battery`, `files` равны `-1`, когда значение неизвестно.
`mode`: 0 — меню/нет измерения, 1 — ЭКГ, 2 — пульс, 3 — SpO₂.
`ms` и время в `ecg` — миллисекунды с запуска, не Unix time.
`utc_ms` — текущие часы ESP32 в UTC миллисекундах, 0 до синхронизации NTP.
`ecg_ok` — оценка пригодности, не аппаратный детектор отрыва электродов.
`dropped` — суммарное число отсчётов, не поместившихся в сетевой буфер.
При перегрузке пропуск обозначается временными метками; это не гарантированный
беспропусковый диагностический поток. Полная запись остаётся на SD.

```json
{"type":"live","seq":1,"ms":12345,"utc_ms":0,"mode":0,"hr":-1,"ecg_hr":-1,"spo2":-1,"battery":-1,"finger":false,"ecg_ok":false,"sd":true,"recording":false,"files":2,"dropped":0,"ecg":[]}
```

Команда `LIST\n`: отдельная строка для каждого завершённого файла, затем `list_end`.

```json
{"type":"entry","name":"ecg_000000001.csv","size":12345}
{"type":"list_end"}
```

Команда `GET ecg_000000001.csv\n`: строка `file`, **ровно size байт CSV**, затем
строка `end`. Читатель должен использовать один буферизированный байтовый поток,
не смешивать `BufferedReader` с сырым сокетом (это может потерять часть CSV).

```json
{"type":"file","name":"ecg_000000001.csv","size":12345}
{"type":"end","crc32":1234567890}
```

CRC32 — IEEE, unsigned, полином `0xedb88320`, начальное и финальное XOR `0xffffffff`.
CRC проверяет повреждение передачи, а не подлинность. Путь `../`, произвольные имена,
открытый файл записи и отсутствующая карта отклоняются строкой `type:error`.
Телефон ограничивает JSON-строку 8192 байтами, проверяет версию, имя и размер,
отклоняет NaN/Infinity и учитывает флаги достоверности CSV. Неполный импорт
откатывается; следующая попытка начинается заново, без возобновления с середины.

## Ограничения и диагностика

Соединение пока **без TLS, авторизации и сопряжения**: любой клиент доверенной
локальной сети технически может прочитать этот сервис. Не открывайте порт в интернет.
Это локальный учебный прототип, не готовая система защищённого обмена медданными.
Исходные CSV в приватном каталоге телефона не имеют дополнительного шифрования;
ключ существующей SQLCipher БД также пока является общей заглушкой в исходнике.
Клинический анализ из прошивки автоматически в Android не переносится.

Если прибор не найден: проверьте подключение Wi-Fi на обоих устройствах, отключение
изоляции клиентов/гостевой сети и доступность mDNS. При ошибке памяти освободите
место телефона; перед копированием оставляется резерв 16 МиБ, но БД тоже занимает
дополнительное место. Отсутствие SD не мешает текущим показаниям.

Реализация обнаружения использует [Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd)
и [NsdManager](https://developer.android.com/reference/android/net/nsd/NsdManager).
Для старых Android добавлен multicast lock; для соединений выбирается Wi-Fi,
чтобы локальная сеть могла работать и без доступа к интернету.

## Проверки

```sh
python3 'Monitor soft/tests/run.py'
cd CardioMonitorApp
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

`LocalProtocolTest` проверяет границы JSON/CSV, усечённые/слишком длинные сообщения,
запрет обхода путей, разные порядки столбцов Pulse/SpO₂, mixed ECG/PPG,
флаги качества и нечисловые значения. Сборка ESP32 проверяется отдельно Arduino CLI.

### Проверено на оборудовании 10 октября 2026

Прошивка собрана для `esp32:esp32:makergo_c3_supermini`, записана на ESP32-C3,
контрольная сумма flash подтверждена загрузчиком. APK собран, установлен и запущен
на Samsung SM-S911B. Телефон автоматически обнаружил плату в общей сети, получил
статус и скопировал обе имевшиеся завершённые записи. CRC32 передачи проверены;
SHA-256 оригиналов SD и копий телефона совпали. Повторная синхронизация оставила те
же два файла и отметки импорта. Запрос пути `../settings.csv` отклонён.
Проверены 20 последовательных кадров LIVE; во время этой проверки прибор был
в меню, без активной записи и валидных показаний. После обновления прошивки и APK
приложение снова установило соединение; ошибок AndroidRuntime в проверенном фрагменте
лога не было. Это проверка транспорта и истории, не измерительной точности и не
длительный тест потока ЭКГ с одновременным скачиванием большой карты.
Девять Android-тестов и шесть групп native-тестов прошли успешно.

### Дата начала измерения

Новые CSV содержат, например:

```text
# started_at_unix_ms=1791586800123
```

Это UTC Unix time в миллисекундах. Время строк `millis_ms` остаётся относительным;
конец сессии в приложении вычисляется как начало плюс длительность. Файл может
содержать комментарий даты в середине или конце, если NTP стал доступен позднее.
Парсеры прошивки и Android читают его независимо от положения. При последующей
коррекции часов уже записанное время начала не меняется. Короткая запись, закрытая
до первой синхронизации после потери питания, останется без даты.

Проверки парсера покрывают ранний/поздний комментарий, недопустимые даты, конфликтующие
повторные комментарии, сохранение относительных отсчётов и старые файлы без даты.
Android: 13 тестов; native: 6 групп, включая даты в анализе истории.

Обоснование ограничения питания: [часы ESP32-C3 и SNTP](https://docs.espressif.com/projects/esp-idf/en/v4.4.6/esp32c3/api-reference/system/system_time.html).
Для будущей автономной версии: [RTC DS3231 с резервным питанием](https://www.analog.com/en/products/ds3231.html).

Проверка обновления дат на оборудовании: новая прошивка загружена на ESP32-C3,
контрольная сумма flash подтверждена. При остановленном процессе Android-приложения
ESP32 самостоятельно получил UTC через NTP. На контрольном чтении его время
отличалось от часов компьютера на 23 мс (это разовая проверка, не гарантия точности
часов). Приложение больше не отправляет команды установки времени. Запись при
доступной SD включена всегда: устаревший скрытый параметр NVS `record` игнорируется.
